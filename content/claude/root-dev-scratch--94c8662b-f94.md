No GPU needed — conversion + quant are CPU/RAM ops. Just needs enough disk for the fp16 intermediate (~2× the param count in GB).

❯ should I do imatrix / split model for the gguf-my-repo?

Short answer for a small Gemma: imatrix only if you're going below Q5; split

imatrix (importance matrix)
- It's a calibration pass — runs the model over a text corpus to weight which tensors matter most, then quantizes to protect them. The Space computes it for you (default calibration
data, or you point at one).
- Payoff scales inversely with bit width:
  - IQ-series and Q2/Q3/Q4 → yes, do it. imatrix is basically mandatory to maworth using, and it noticeably helps Q3_K*/Q4_K_M.
  - Q5_K_M / Q6_K / Q8_0 → skip. The quality gap vs. no-imatrix is within noise, and it just adds Space runtime (a spot where the free Space likes to time out).
- One caveat: the default calibration corpus is generic English. If your finerpay/GTM text, code, non-English), a generic imatrix can be slightly mismatched — not harmful, just not maximally helpful. Only worth feeding a custom calibration file if you're squeezing a low-bit quant hard.

Split model
- Purely a packaging/transport feature: shards the GGUF so no single file excnd downloads resume better. llama.cpp/Ollama load sharded GGUF transparently.
- A small Gemma quant is a few hundred MB to a couple GB — splitting buys you nothing and just makes the repo messier. Leave it off. Only turn it on for big models (30B+ at high
precision) that blow past the single-file limit.
