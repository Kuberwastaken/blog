## OpenCode Model Catalog & Selection Architecture

### Executive Summary

OpenCode implements a **multi-source, always-fresh model catalog** that prevents the "stuck-on-old-model" bug through:
1. **Dynamic catalog merging** from three sources (models.dev + user config + plugin discovery)
2. **Cache with automatic TTL refresh** (5-min staleness check, 60-min refresh loop)
3. **Default model computed at runtime** (never hardcoded), derived from freshest available models
4. **Plugin-driven model discovery** that supplements the static catalog without requiring releases

### How It Prevents "Stuck-on-Old-Model" Bug

#### **1. Multi-Source Merge**
- Catalog is NOT a single static list
- Combines: models.dev + user config + plugin discovery
- User config can add/override models any time (no release needed)
- Plugins can discover models at runtime (e.g., GitLab workflows)

#### **2. Continuous Refresh Loop**
```typescript
// Line 233–236 of models-dev.ts
if (!Flag.OPENCODE_DISABLE_MODELS_FETCH) {
  yield* Effect.forkScoped(
    refresh().pipe(
      Effect.repeat(Schedule.spaced("60 minutes")),
      Effect.ignore
    )
  )
}
```
- Background task refreshes models every 60 minutes
- No restart needed; next call to `get()` sees fresh data
- Can also call `opencode models --refresh` to force immediate sync

#### **3. TTL-Based Staleness Check**
```typescript
// Lines 146–151 of models-dev.ts
const fresh = Effect.fnUntraced(function* () {
  const stat = yield* fs.stat(filepath)
  const mtime = stat.mtime.getTime()
  return Date.now() - mtime < Duration.toMillis(ttl)  // 5 min
})
```
- Cache older than 5 minutes is considered stale
- On stale detection + background refresh: no blocking, cache is still usable

#### **4. Default Model is Runtime-Computed**
```typescript
// Lines 1913–1945: defaultModel() effect
// NOT: const DEFAULT_MODEL = "claude-sonnet-4"
// INSTEAD: read from current state, sort, pick first
```
- Default is not a hardcoded string
- Recomputed every time `defaultModel()` is called
- Always reflects what's currently available & configured

#### **5. Plugin Discovery Runs At Init**
```typescript
// Lines 1563–1575
const gitlab = ProviderV2.ID.make("gitlab")
if (discoveryLoaders[gitlab] && providers[gitlab]) {
  yield* Effect.promise(async () => {
    const discovered = await discoveryLoaders[gitlab]()
    for (const [modelID, model] of Object.entries(discovered)) {
      if (!providers[gitlab].models[modelID]) {
        providers[gitlab].models[modelID] = model
      }
    }
  })
}
```
- Plugins like GitLab can discover models dynamically
- These are merged into the catalog upfront
- No hardcoded model list in code

### Design Principles That Enable Robustness

1. **Separation of Concerns:**
   - Models.dev = source of truth (upstream)
   - Cache = fast reads, TTL-based freshness
   - Config = user overrides, doesn't require release
   - Plugins = extensible discovery, runtime

2. **Lazy + Background Refresh:**
   - Blocking fetches use 5-min cache to avoid hangs
   - Background loop refreshes without blocking user
   - No "stuck" state if models.dev is temporarily down

3. **No Hardcoding:**
   - No default model ID in code
   - No provider-specific "latest" logic baked in
   - Defaults derived from catalog at selection time

4. **User Control:**
   - `OPENCODE_MODELS_URL`: Point to custom models.dev mirror
   - `OPENCODE_MODELS_PATH`: Load snapshot from local file
   - `opencode.json` provider.model overrides
   - `opencode models --refresh`: Force sync

5. **Plugin Extensibility:**
   - Plugins can add/modify models without code changes
   - Discovery hooks run at initialization
   - Custom loaders (anthropic, bedrock, etc.) integrate seamlessly

---

### Example: How a New Model Gets Picked Up

**Scenario:** A new Claude model is released on models.dev

1. **Automatic (within 60 min):** Background refresh loop calls `refresh()` → fetches models.dev → invalidates cache
2. **On next API call:** `Provider.defaultModel()` calls `sort(Object.values(provider.models))` → new model is in the list → sorts by release_date DESC → new model wins
3. **Or immediate (manual):** User runs `opencode models --refresh` → force-fetches → cache invalidated → next call sees it
4. **Or via config:** User adds to `opencode.json` without waiting for release

**No restart, no hardcoded fallback, no stale version.**

Based on opencode's design:

**❌ Anti-patterns:**
- Hardcoded `const DEFAULT_MODEL = "claude-3-sonnet"` in code
- Single-source catalog loaded at build time
- No cache refresh loop
- Provider-specific overrides that bypass catalog

**✅ Patterns to adopt:**
- Runtime-computed defaults from mergeable catalog
- Multi-source merge (static + config + discovery)
- TTL-based cache + background refresh loop
- Env/config overrides that don't require release
