Adding the context here:

I'd been working on the outbound pipeline with Gemini 2.5 Flash as the intelligence layer, with having model cost tracking built in from token estimates - which was quite accurate, However, Google Search grounding was enabled by default as part of the Gemini tool configuration, and I assumed it was covered within the model/tool cost when I received my key from the project -  but as we found out, on Vertex it does get billed as a separate SKU after the included allowance.

For approximately 400k rows of enrichment, the expected model inference cost was ₹60–65k. The grounding usage, however, accumulated approximately ₹8 lakh over nine days.

We found out about a anomaly in % rise earlier today - and had to spend ~45 minutes with the CLI piecing things together because the billing view initially available to us showed aggregate project spend, so isolating the source required admin access and eventually a detailed billing CSV export, where we identified the grounding SKU. The billing data did not provide clear per-key cost attribution, and this setup did not have a grounding-specific hard spend cap.

I should've absolutely had some discussion about cap on the project to not find out later and for everyone running similar pipelines, it would be worth checking whether any tools are billed separately and ensuring that budget alerts and application-level limits are in place before scaling.

I'll be spending time working on more hosted solutions (better than the current SearXNG) and share about the same as well.
